# 二、项目定位

项目暂定名称：

中文名：研途智选
英文工作名：ResearchNavigator

这是一个面向研究生、科研初学者和准备进入新研究方向的用户的“证据驱动科研选题与论文研究工作台”。

它不是普通论文聊天机器人，也不是简单的论文搜索聚合器。

核心闭环是：

用户研究档案
→ 大方向拆解
→ 文献检索
→ 经典论文与前沿论文推荐
→ 论文结构化理解
→ 方向匹配度与复现推荐度
→ 候选研究空白
→ 反证检索
→ 研究问题确认
→ 阅读和复现计划
→ 收藏、笔记、任务和进度长期沉淀

默认示范研究方向为：

- 多变量时序异常检测；
- 工业时序异常预警；
- 历史窗口到未来 Horizon 的异常风险预测；
- 有限告警预算下的异常排序；
- 伪正常记忆和真实异常记忆；
- 高误报环境下的安全告警抑制；
- 不确定性与异常冲突处理。

但系统架构不能硬编码为只支持时序异常检测，应支持用户创建其他研究方向。

# 三、产品目标与非目标

## 3.1 产品目标

系统至少帮助用户完成：

1. 建立自己的研究方向档案；
2. 将宽泛方向拆成任务、数据、方法、应用和评价维度；
3. 检索并聚合多个论文数据源；
4. 打开论文原始网页、DOI 页面、arXiv 页面或出版社页面；
5. 查看论文摘要、研究问题、方法、算法、数据集、实验、贡献、Future Work 和不足；
6. 区分作者明确写出的 Future Work 与系统推断的潜在不足；
7. 查看论文与用户研究方向的匹配度；
8. 查看论文复现推荐度及评分依据；
9. 收藏论文、添加标签、写笔记并保存阅读状态；
10. 推荐经典论文、综述论文、代表论文和近期前沿论文；
11. 基于一组论文生成候选研究空白；
12. 对候选研究空白执行反证检索；
13. 将选定方向转换成阶段性阅读、复现和实验计划；
14. 在关机、重启和重新打开网页后保留全部记录；
15. 让同组学生通过局域网 URL 使用系统，并隔离各自的数据。

## 3.2 非目标

第一阶段不要实现：

1. 自动替用户证明某项研究绝对没有人做过；
2. 自动生成可以直接投稿的完整论文；
3. 绕过出版社登录、学校代理或付费墙；
4. 未经授权批量下载受版权保护的全文；
5. 根据期刊分区或引用量直接判断论文质量；
6. 用一个不可解释的 LLM 分数代替复现评估；
7. 实现复杂社交网络、导师管理或科研经费管理；
8. 一开始就支持大规模商业 SaaS；
9. 让多个自由 Agent 无限制互相对话；
10. 将未实际接通的 API 写成“已经集成”。

# 四、关键事实与科研主张边界

必须在产品、PRD、TechDocs 和代码中执行以下约束。

## 4.1 研究空白表述

禁止输出：

- “这个问题从未有人研究过。”
- “这是一个确定的新研究空白。”
- “这个方向具有绝对创新性。”

允许输出：

- “在本次检索的数据源、查询式和时间范围内，该组合的直接研究证据较少。”
- “这是一个候选研究空白，需要进一步扩展检索和专家确认。”
- “当前证据支持度为中等，但存在以下可能推翻该判断的相邻研究。”

每个候选研究空白必须包含：

- gap_id；
- 候选空白陈述；
- 空白类型；
- 适用范围；
- 支持论文；
- 相邻但不完全相同的论文；
- 可能构成反证的论文；
- 使用的数据源；
- 中英文检索式；
- 检索过滤条件；
- 检索时间；
- 检索结果数量；
- 纳入与排除理由；
- 证据覆盖度；
- 置信等级；
- 风险说明；
- 建议的最小验证实验；
- “本结果不是创新性证明”的固定提示。

## 4.2 论文分析证据等级

每份论文分析都必须显示 evidence_level：

- metadata_only：只有题目、作者、年份、期刊等元数据；
- abstract_only：能够读取摘要；
- open_fulltext：读取了合法开放全文；
- user_uploaded_fulltext：用户上传了其有权使用的 PDF；
- publisher_authorized_fulltext：通过合法授权 API 获取全文。

当只有摘要时，不得输出论文中未在摘要中出现的具体网络结构、损失函数、实验参数或 Future Work。

没有找到的内容必须显示：

“未在当前可访问文本中找到。”

不能由模型自行补齐。

## 4.3 Future Work 和不足分类

论文详情页必须区分：

1. 作者明确陈述的 Future Work；
2. 作者明确陈述的 Limitations；
3. 系统基于证据推断的潜在限制；
4. 用户自己添加的批判性笔记。

第三类必须标记为“系统推断”，并提供推断依据。

## 4.4 作者贡献

若论文包含 CRediT Author Statement，则可以展示论文级作者角色。

若没有 CRediT 声明，不得猜测每位作者分别完成了什么。

作者卡片可以展示：

- 规范化作者名称；
- ORCID 或学术数据库作者 ID；
- 所属机构；
- 研究主题分布；
- 代表论文；
- 论文时间线；
- 合作者；
- 引用和论文数量等来源可验证信息；
- 作者消歧置信度。

不能将同名作者直接合并。

# 六、核心用户流程

## 6.1 首次使用

1. 用户注册或使用管理员提供的邀请码；
2. 填写研究阶段：
   - 硕士一年级；
   - 硕士二年级；
   - 博士；
   - 转方向；
   - 其他；
3. 填写专业和已有知识；
4. 选择宽泛方向；
5. 输入导师给出的方向；
6. 输入已有论文、关键词和排除词；
7. 输入可使用的数据、算力、时间和代码能力；
8. 设置偏好：
   - 理论研究；
   - 方法研究；
   - 工程应用；
   - 数据研究；
   - 复现优先；
   - 发表优先；
9. 生成研究方向档案；
10. 用户必须可以人工修改所有系统推断内容。

## 6.2 论文搜索

用户可以搜索：

- 关键词；
- 完整题目；
- DOI；
- arXiv ID；
- 作者；
- 期刊或会议；
- 研究任务；
- 方法；
- 数据集；
- 时间范围。

支持：

- 中文输入扩展为英文关键词；
- AND、OR、NOT；
- 年份筛选；
- 论文类型筛选；
- 开放全文筛选；
- 有代码筛选；
- 有公开数据筛选；
- 按相关度、时间和引用信息排序；
- 保存搜索式；
- 查看本次搜索调用了哪些数据源；
- 查看数据源失败或限流状态。

搜索结果必须去重。

优先去重键：

1. DOI；
2. arXiv ID；
3. PubMed ID 或其他稳定 ID；
4. 标准化标题 + 年份 + 第一作者；
5. 标题相似度只能作为候选，不能直接静默合并。

## 6.3 论文详情

论文详情页至少包括：

- 题目；
- 中文标题；
- 作者；
- 机构；
- 年份；
- 期刊或会议；
- DOI；
- arXiv ID；
- 来源数据源；
- 数据更新时间；
- 摘要；
- 中文简介；
- 研究背景；
- 研究问题；
- 输入和输出；
- 核心方法；
- 新算法或新模块；
- 实验设计；
- 使用的数据集；
- 基线；
- 指标；
- 主要结果；
- 贡献；
- Future Work；
- 作者声明的局限；
- 系统推断的局限；
- 与用户方向的相似度；
- 复现推荐度；
- 代码和数据链接；
- 引用论文；
- 被引论文；
- 相似论文；
- 证据等级；
- 引用定位；
- 收藏、标签、笔记和阅读状态；
- 跳转到原始网页。

每项结构化分析必须能够回到：

- 摘要；
- 章节；
- 页码；
- chunk_id；
- 外部来源。

## 6.4 候选研究空白

用户选择一个研究问题或一组论文后，系统执行：

1. 构造研究维度矩阵；
2. 提取论文任务、数据、方法、监督形式、预测目标、实验设置和评价指标；
3. 查找覆盖不足的组合；
4. 生成候选空白；
5. 生成反向检索式；
6. 搜索可能推翻该空白的论文；
7. 更新支持证据和反向证据；
8. 输出置信等级；
9. 要求用户人工确认；
10. 生成最小可行实验建议。

候选空白类型至少包括：

- 任务定义空白；
- 数据场景空白；
- 方法与任务错位；
- 评价协议空白；
- 鲁棒性空白；
- 部署和资源约束空白；
- 不确定性空白；
- 跨设备或跨领域泛化空白；
- 负结果或复现空白；
- 相邻工作之间未覆盖的组合。

系统不能仅根据“关键词共现少”就判断研究空白。

# 七、数据源设计

## 7.1 默认开放数据源

优先实现适配器：

1. OpenAlex；
2. Crossref；
3. arXiv；
4. Semantic Scholar；
5. Unpaywall。

根据可用性选配：

- CORE；
- PubMed；
- DBLP；
- OpenReview；
- Papers with Code。

## 7.2 授权数据源

以下数据源只能作为需要凭据的可选适配器：

- Web of Science；
- Elsevier/ScienceDirect；
- Scopus；
- 学校图书馆授权资源。

实现要求：

1. 所有凭据仅保存在服务端环境变量；
2. 前端不能获取 API Key；
3. 没有凭据时显示“未配置”，而不是报系统错误；
4. 提供 .env.example；
5. 提供管理员数据源配置页；
6. 提供连通性测试；
7. 不得模拟登录；
8. 不得绕过付费墙；
9. 不得违反 robots、API 条款或版权要求；
10. 不得把模拟数据写成真实搜索结果。

## 7.3 papers.cool

将 papers.cool 设计为：

- arXiv 论文的可选外部阅读链接；
- 会议页面或相关论文的补充入口；
- 只有在确认其公开接口、路由和使用方式符合要求后才实现程序化接入。

不要把它作为唯一底层论文索引。

## 7.4 统一论文数据模型

所有适配器必须转换到统一 PaperRecord。

至少包含：

- internal_id；
- title；
- normalized_title；
- translated_title；
- abstract；
- publication_year；
- publication_date；
- authors；
- author_ids；
- affiliations；
- venue；
- venue_type；
- doi；
- arxiv_id；
- external_ids；
- source_urls；
- publisher_url；
- pdf_url；
- open_access_status；
- citation_count；
- reference_count；
- fields_of_study；
- concepts；
- keywords；
- source_provenance；
- fetched_at；
- raw_record_hash。

保留原始数据源 provenance，不能只保存融合后的结果。

# 八、RAG 设计

## 8.1 可使用的语料

允许进入 RAG 的内容：

1. 公开摘要；
2. 合法开放全文；
3. 用户上传且用户确认有权使用的 PDF；
4. 经过授权 API 获取的全文；
5. 用户自己的笔记。

不允许：

- 绕过权限获取的全文；
- 搜索结果中截断的片段被误当成全文；
- 模型根据题目自行生成的“伪全文”。

## 8.2 文档处理

实现以下流程：

文档解析
→ 章节识别
→ 文本清洗
→ 结构化切块
→ 元数据绑定
→ 向量化
→ 全文检索
→ 混合召回
→ 可选重排
→ 有证据回答
→ 引用校验

切块优先按论文结构：

- Abstract；
- Introduction；
- Related Work；
- Method；
- Experiments；
- Results；
- Limitations；
- Conclusion；
- Appendix。

每个 chunk 必须保存：

- paper_id；
- section；
- page_start；
- page_end；
- chunk_index；
- text_hash；
- source_type；
- evidence_level；
- ingestion_version。

## 8.3 检索

V1 至少实现：

- SQLite FTS5 或等价 BM25；
- 向量召回；
- 混合分数；
- top_k 配置；
- 引用返回。

不要只调用 LLM 的长上下文而称为 RAG。

允许使用：

- Chroma、LanceDB 或其他本地持久向量库；
- SQLite 保存业务记录；
- 向量索引目录也必须挂载到持久化目录。

## 8.4 结构化论文分析 Schema

使用 Pydantic 和 JSON Schema 定义，不允许只返回自由文本。

示例字段：

{
  "paper_id": "...",
  "evidence_level": "abstract_only",
  "analysis_version": "...",
  "summary": "...",
  "research_background": "...",
  "research_problem": "...",
  "task_definition": {
    "input": "...",
    "output": "...",
    "setting": "..."
  },
  "methods": [],
  "novelty_claims": [],
  "datasets": [],
  "baselines": [],

## 8.5 RAG 质量评价

至少建立一组开放论文测试集，评价：

- Retrieval Hit Rate；
- Citation Precision；
- Citation Coverage；
- Answer Faithfulness；
- Structured Extraction Accuracy；
- 不存在字段的拒答准确率；
- 摘要级与全文级结果边界；
- PDF 解析失败率。

不要只使用“看起来回答合理”作为验收。

# 九、方向匹配度

方向匹配度不能只让 LLM 输出一个 87%。

实现可解释的组合评分。

建议默认维度：

- 语义相似度：35%；
- 研究任务一致性：25%；
- 数据模态和应用场景：15%；
- 预测目标或输出形式：10%；
- 实验和评价协议：10%；
- 用户资源约束：5%。

缺失字段使用 missing-aware normalization：

score =
sum(weight_i × component_score_i × available_i)
/
sum(weight_i × available_i)

同时输出：

- 总分；
- 各组成分；
- 可用证据覆盖率；
- 评分理由；
- 不匹配原因；
- 评分版本。

针对时序异常检测示例，需要区分：

- 异常检测；
- 异常预测；
- 未来窗口风险；
- 故障预测；
- 剩余寿命预测；
- 变化点检测；
- 点级分类；
- 事件级预警；
- 固定预算排序。

不能因为都包含 anomaly 关键词就判定为高度相似。

# 十、复现推荐度

复现推荐度必须基于可观察证据，不允许完全由 LLM 主观评分。

默认维度：

- 官方或作者代码可用性：20%；
- 数据可用性：20%；
- 方法描述完整性：15%；
- 环境和依赖说明：10%；
- 超参数说明：10%；
- 计算资源适配：10%；
- 评价协议完整性：10%；
- 许可证清晰度：5%。

每一项输出：

- 得分；
- 证据；
- 状态：verified、partial、unknown、missing；
- 来源；
- 检查时间。

总结果同时显示：

- reproduction_score；
- evidence_coverage；
- estimated_difficulty；
- estimated_compute_level；
- blocking_reasons；
- recommended_first_step。

unknown 不能等同于 missing。

若没有检查代码仓库、数据链接和论文正文，不能输出高置信复现评分。

# 十一、经典论文与前沿论文推荐

推荐结果分为：

1. 入门综述；
2. 经典基础论文；
3. 任务定义代表论文；
4. 关键方法论文；
5. 高相关近期论文；
6. 反向或不同路线论文；
7. 最适合复现的论文。

不要将“引用量高”等同于“适合用户”。

每篇推荐必须说明：

- 推荐类别；
- 推荐原因；
- 与用户方向的关系；
- 推荐阅读顺序；
- 阅读前置知识；
- 是否建议复现；
- 可能误导用户的地方。

“经典论文”和“顶刊顶会”标签的来源、规则和版本必须可配置和审计。

# 十二、候选研究空白引擎

- 是否评价事件级指标；

- 是否提供数据；

- 作者 Limitations。

只有完成 challenge search 后，候选空白才可以进入“待人工确认”。

# 二十二、测试要求

采用测试驱动或至少测试先行的方式。

## 22.1 单元测试

覆盖：

- 论文标准化；
- DOI 标准化；
- arXiv ID；
- 标题去重；
- 作者消歧候选；
- 数据源字段映射；
- 匹配度评分；
- 复现评分；
- evidence level；
- gap candidate；
- 反证检索式；
- 用户权限；
- 数据隔离；
- PDF MIME 和大小检查；
- URL 安全；
- MCP 输入输出 Schema。

## 22.2 集成测试

覆盖：

- 至少两个真实开放论文数据源；
- 数据源超时；
- 429 限流；
- 无摘要；
- 重复 DOI；
- 无开放全文；
- PDF 解析失败；
- LLM 不可用；
- 向量索引重建；
- 数据库迁移；
- worker 重启恢复。

真实外部 API 测试和 mock 测试分开。

没有 API Key 时，授权数据源测试必须明确 skip，不能假装通过。

## 22.3 E2E 测试

使用 Playwright 或等价工具，覆盖：

1. 注册；
2. 登录；
3. 创建研究档案；
4. 创建项目；
5. 搜索论文；
6. 打开详情；
7. 收藏；
8. 添加笔记；
9. 上传合法测试 PDF；
10. 执行论文分析；
11. 创建计划；
12. 退出；
13. 重启服务；
14. 再次登录；
15. 验证记录仍存在。

## 22.4 RAG 评价

建立固定 fixture：

- 开放论文；
- 摘要；
- 预期研究问题；
- 预期数据集；
- 预期方法；
- 明确没有出现的字段。

必须测试模型不会为不存在的信息编造答案。

## 22.5 安全测试

覆盖：

- SQL 注入；
- 越权读取其他用户笔记；
- 路径穿越；
- SSRF；
- 超大 PDF；
- 错误 MIME；
- 恶意文件名；
- API Key 日志泄漏；
- 未登录访问；
- 管理员接口权限。

# 二十三、验收标准

只有同时满足以下条件，才能声明 V1 完成：

1. docker compose up --build 能启动；
2. 前端、API 和 worker 健康检查通过；
3. 可以创建用户和研究项目；
4. 可以从真实开放数据源搜索论文；
5. 搜索结果可以去重；
6. 可以打开真实论文网页；
7. 可以保存收藏、笔记和阅读状态；
8. 可以上传 PDF 并完成 RAG 分析；
9. 论文分析具有引用定位；
10. 只有摘要时不会输出全文细节；
11. 可以生成可解释的匹配度；
12. 可以生成有证据覆盖度的复现推荐度；
13. 可以创建研究计划；
14. 服务重启后记录仍存在；
15. 用户之间数据隔离；
16. 单元测试、集成测试和 E2E 测试通过；
17. 文档和运行命令与实际代码一致；
18. 没有把 mock 数据展示成真实数据；
19. 没有硬编码 API Key；
20. 最终报告列出所有未完成项。

V2 验收还必须包括：

1. 可以生成研究维度矩阵；
2. 候选空白有支持和反向证据；
3. 可以执行 challenge search；
4. 未完成反证检索的空白不能进入已确认状态；
5. 可以人工修改和确认候选空白；
6. 可以从确认的问题生成计划；
7. Agent 运行可中断、失败和恢复；
8. 每次运行有完整审计日志；
9. V1 回归测试通过。

# 二十四、产品指标

PRD 中至少定义：

产品指标：

- 首次获得有效论文的时间；
- 搜索到收藏转化率；
- 论文详情打开率；
- 收藏后再次访问率；
- 计划创建率；
- 任务完成率；
- 用户主动修改 AI 结果的比例；
- 周留存。

检索指标：

- Precision@10；
- Recall@K；
- NDCG@10；
- 重复论文率；
- 数据源失败率；
- 搜索响应时间。

论文分析指标：

- Citation Precision；
- Citation Coverage；
- Faithfulness；
- Structured Extraction Accuracy；
- Missing-field refusal accuracy。

候选空白指标：

- 专家认为“值得进一步查证”的比例；
- 被反证检索推翻的比例；
- 支持和反向证据覆盖度；
- 人工修改率；
- 候选空白到研究计划转化率。

不能用“生成了多少研究空白”作为核心成功指标。
