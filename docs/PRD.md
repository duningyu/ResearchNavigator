## 2.1 本轮真实反馈与产品判断

本轮需求来自真实使用反馈，核心问题不是继续增加科研功能数量，而是修复“功能存在但研究决策链没有闭合”的问题。2.1 将核心范式从 **last-search implicit corpus** 改为 **selection-first evidence workflow**：

`研究方向/项目 -> 明确选择论文集合 -> 单篇证据级分析 -> 证据级对比 -> 候选研究空白 -> Gap Explanation -> Challenge Search -> 真实人工确认 -> 研究计划`

本轮 P0 反馈及处理：

### 2.2 Discovery Search 合同

- `auto`：服务器确定进入 precise/discovery；
- `precise`：DOI、arXiv ID、明确题名、多概念/明确条件检索；
- `discovery`：1–2 个宽泛概念词，例如 `attention`、`异常检测`；
- Discovery 默认面向 Top50，前端可改 Top10/20/50；分页固定每页 10 篇；
- Top50 的 10:40 是候选组成目标，不是保证；真实候选不足时记录 `classic_shortfall/frontier_shortfall`，禁止补造论文；
- `classic_candidate` 只是可审计排序标签，不等价于学界公认“经典”；
- 新会话新 seed；rerun 原会话复用 seed；实时来源变化时，可复现证据定义为 query + filters + sources + status + seed + stable IDs + provenance hashes + timestamp。

### 2.4 V2.2 证据升级闭环

2.2 不把“全文 URL”或“LLM 已调用”直接当作可信分析。完整链路为：

`metadata_only → 可信摘要 → abstract_only → OA 候选与权利策略 → 合法全文安全摄取 → 全文切块 → 确定性分析 → 可选 citation-validated LLM 补充 → 作者/数据集研究卡 → 方向聚类`。

关键产品约束：

- 旧 `/acquire-evidence` 保持摘要级兼容，新完整流程通过持久工作流执行；
- 未知许可证只提供 `link_only`，不自动保存；
- OpenAlex 429 只使该来源 degraded/rate_limited，其他来源继续；
- 历史摘要不会由迁移批量标可信，必须严格重新获取或上传合法全文；
- 作者同名不自动合并，数据集缺失字段不补造，方向聚类不宣称客观 taxonomy；
- 专家评测基础设施与真实专家验证分离，没有真实外部评分时保持 `awaiting_real_experts`。

### 2.5 证据边界

每个深度分析字段必须显示 `evidenced / unknown / insufficient_evidence`。摘要级分析不能推断全文实验协议、未出现的数据集、显式 Future Work 或作者声明局限。当前确定性解析保存 page/chunk 级 provenance，但尚不能把每个句子自动证明为由某一个具体 chunk 蕴含，因此不得把 field citation 描述成完整 sentence-level entailment。

## 3. 产品背景

研究生进入陌生方向时，常面对三个不同问题：不知道该检索什么、不知道论文之间的任务边界、不知道所谓“研究空白”是否只是术语差异或检索遗漏。现有工具通常分别优化论文搜索、PDF 问答、系统综述或引用图谱，而选题决策需要把用户约束、论文证据、反向检索和可执行计划连接起来。

本产品不把“多 Agent”作为卖点。Agent 只编排需要状态、工具调用和人工确认的长流程；普通 CRUD、评分和访问控制保持确定性。

## 4. 用户问题

1. 导师只给出宽泛方向，用户无法拆成任务、数据、方法、输出和评价协议；
2. 用户能搜索论文，但难以判断经典、代表性、前沿和适合复现的区别；
3. 摘要级 AI 总结容易补写未出现的方法、参数和 Future Work；
4. “相似度 87%”或“复现推荐 90%”常缺少组成证据；
5. 研究空白判断容易受关键词、数据库覆盖和时间范围影响；
6. 收藏、笔记、搜索式、计划散落在多个工具，重启后或换会话难以恢复；
7. 同组学生需要在局域网使用，但个人笔记和计划必须隔离。

## 5. 目标用户

- 硕士一年级：需要建立方向地图和阅读顺序；
- 硕士二年级：需要收敛问题、选择复现对象和最小实验；
- 博士或转方向研究者：需要快速构建证据矩阵和反证路径；
- 研究小组：需要一台实验室电脑局域网部署，但不要求大规模 SaaS。

## 6. Persona

### Persona A：初入时序异常检测的硕士生

- 输入：导师给出“做时序数据异常检测”；
- 约束：单卡 GPU、半年以内形成实验、缺少系统综述经验；
- 目标：区分异常检测、异常预测、未来窗口风险、故障预测和剩余寿命；
- 风险：把高引用点异常检测论文误当成未来窗口预警直接基线。

### Persona B：已有实验但需要收敛论文主张的硕士生

- 输入：若干 baseline、实验日志和候选模块；
- 目标：寻找评价协议或任务定义上的候选空白；
- 风险：反复查看测试集、把规则后处理包装成方法创新。

## 7. JTBD

- 当我只知道一个宽泛研究方向时，我希望得到可修改的任务分解和检索路径，以便建立可信阅读清单；
- 当我打开一篇论文时，我希望知道结论来自摘要还是全文，以便控制引用和理解风险；
- 当我考虑复现时，我希望看到代码、数据、方法、环境、协议和许可的分别状态，以便识别阻断项；
- 当系统提出研究空白时，我希望看到可能推翻它的查询和论文，以便避免把检索遗漏当创新；
- 当我确认方向后，我希望生成阶段性计划并在关机后保留，以便持续推进。

## 8. 用户调研假设

需要后续真实验证，不能把假设写成结论：

1. 新入组研究生最先需要任务边界，而不是更长的论文总结；
2. 可解释相似度比单一 LLM 分数更能支持选题；
3. challenge search 会降低“错误空白”的确认率，但增加决策时间；
4. 本地持久化和局域网访问对实验室小组有实际价值；
5. 同组用户愿意人工修改 AI 输出，而不是直接接受。

建议访谈至少覆盖：已入方向研究生、正在转方向者、导师/博士生、与目标方向无关的可用性测试者。

## 9. 用户旅程

1. 注册并填写阶段、专业、导师方向、关键词、排除词、算力和偏好；
2. 创建研究项目；
3. 输入中文或英文查询，查看数据源状态和真实/fixture 标记；
4. 打开论文元数据和原始网页；
5. 基于摘要或用户有权上传的 PDF 执行结构化分析；
6. 查看方向匹配度、证据覆盖和复现阻断项；
7. 收藏、标签、记录批判性笔记和阅读状态；
8. 选择论文形成证据矩阵；
9. 生成候选空白；
10. 执行 challenge search；
11. 人工审阅支持与反向证据；
12. 确认、拒绝或修改候选；
13. 生成阅读、复现、数据准备、最小实验和失败退出计划；
14. 持续更新任务和搜索记录。


### 9.1 2.1 Selection-first 主旅程

1. 登录并维护研究档案；
2. 创建/选择研究项目，明确当前研究方向；
3. 搜索论文；模糊词进入 Discovery，可选择 Top10/20/50；
4. 通过 search session URL 恢复查询、页码和持久排序；
5. 打开论文执行证据级分析，必要时上传有权使用的 PDF；
6. 收藏论文或从明确 search session/题名检索中选择论文；
7. 将选择固化为 `PaperSet`，而不是默认最近一次搜索；
8. 选择项目/方向后运行证据级论文对比；
9. 用选定论文 + 当前方向生成候选 Gap；
10. 查看 Gap Explanation 的直接证据、推断、反向证据、缺失项和创新风险；
11. 执行 Challenge Search；
12. 默认停止在 `awaiting_human_confirmation`，由用户真实点击确认/拒绝；
13. 仅真实确认后生成计划；
14. Jobs 页面查看终态、重试、取消；Settings/Admin/Source Test/Backup 页面完成平台维护。

## 10. 当前替代方案

- 搜索引擎/数据库：Google Scholar、Web of Science、ScienceDirect、OpenAlex、Semantic Scholar；
- 文献管理：Zotero、表格、Notion；
- AI 阅读：Elicit、Consensus、SciSpace 等；
- 图谱发现：ResearchRabbit、Connected Papers；
- 研究计划：手工文档或通用任务工具。

这些工具可以组合使用，但用户需要手工维护任务边界、证据等级、反向检索和计划状态。

### 差异化假设

本产品的差异化不在“更会总结论文”，而在：

1. 用户研究约束进入匹配和计划；
2. 摘要/全文证据等级显式约束结构化字段；
3. 复现推荐把 unknown 与 missing 分开；
4. 候选研究空白必须经过 challenge search；
5. 人工确认是状态转换条件；
6. 本地优先、SQLite 持久和局域网部署。

这些仍是产品设计差异，不代表实际效果优于竞品，需用户实验和检索评测支持。

## 12. 产品定位

> 面向研究生的证据驱动科研选题与论文研究工作台：帮助用户从宽泛方向建立论文证据、反向查证候选空白，并形成可执行研究计划。

## 13. 差异化价值

- 把“搜索结果”升级为可审计检索会话；
- 把“论文总结”约束为 evidence-level 结构化分析；
- 把“相似度”拆成任务、数据、输出、协议和资源组成；
- 把“复现推荐”拆成可观察状态和阻断项；
- 把“研究空白”变成支持证据 + 反向证据 + 人工确认；
- 把“一次性对话”变成重启后仍存在的项目工作区。

## 14. 产品目标

1. 用户可在 10 分钟内建立方向档案并获得第一批可追溯论文；
2. 所有 AI/确定性分析均显示 evidence level；
3. 所有候选研究空白保留查询、来源、反证和主张边界；
4. 用户可从确认问题生成计划并持续更新；
5. 服务重启后状态保留；
6. 同一局域网多用户数据隔离。

## 15. 非目标

- 证明某研究从未被做过；
- 绕过登录、学校代理或付费墙；
- 生成可直接投稿的完整论文；
- 用期刊分区或引用量直接判断质量；
- 把未核验代码、数据和 API 写成已接入；
- 大规模商业 SaaS、复杂组织权限、科研经费管理；
- 无限制多 Agent 自由对话。

## 16. 功能架构

- 身份与工作区：用户、研究档案、项目；
- 论文发现：适配器、标准化、去重、来源状态、搜索历史；
- 论文理解：元数据、摘要、PDF、切块、混合召回、结构化分析；
- 决策辅助：方向匹配、复现评估、收藏、笔记、显式 PaperSet、证据级对比；
- 研究空白：选定论文 + 方向快照、证据矩阵、Gap Explanation、Challenge Search、人工确认；
- 执行计划：计划、任务、终态/重试/取消；
- 平台：用户设置、管理员安全配置、来源主动测试、SourceRequest 审计、worker、MCP、HTTP-first Harness、幂等、备份/重启恢复、Docker。

## 18. V2 功能需求

### P0

- 研究维度矩阵；
- 候选空白固定 disclaimer；
- 同义词、邻近任务、旧术语、方法反查等 challenge queries；
- 反向证据候选；
- 未 challenge 不可确认；
- 人工确认/拒绝；
- 从确认问题生成计划；
- AgentRun、Job、工具调用和输出哈希审计。

### P1

- 主题聚类与研究版图；
- 经典/综述/代表/前沿/反向/适合复现分层推荐；
- 数据集卡和作者研究轨迹；
- 周期性更新。

### P2

- 专家标注集驱动的 gap 质量模型；
- 跨项目迁移和小组协作。

## 19. P0/P1/P2 原则

- P0：没有它，核心闭环不成立或存在严重科研风险；
- P1：提升决策效率，但不影响证据边界；
- P2：规模化、体验或高级研究能力。

## 20. 用户故事

- 作为硕士生，我能输入导师方向并修改系统拆解；
- 作为用户，我能看到每条论文分析来自摘要还是全文；
- 作为用户，我能点击原始网页而不是被困在系统内；
- 作为复现者，我能看到 unknown 与 missing 的区别；
- 作为选题者，我无法跳过反证检索直接确认候选空白；
- 作为同组成员，我不能读取其他用户的笔记、收藏和计划；
- 作为管理员，我能看到数据源未配置，而不是伪成功。

## 21. 验收标准

V1：真实开放源搜索、去重、原始链接、持久收藏笔记、PDF 证据检索、摘要不越界、可解释评分、重启保留、隔离、测试和文档。

V2.1：除 V1/V2 回归外，必须验证 Discovery seed/composition、显式 PaperSet、不依赖最近搜索、深度 evidence fields、证据级 comparison、Gap Explanation、收藏联动、PDF 生命周期、Settings/Admin/Jobs/Source Test、幂等、HTTP-first 场景、worker terminal state、备份恢复；窄屏导航与完整浏览器闭环必须由 Playwright 当前环境实际执行后才能标 PASS。

具体自动化与环境状态见 `delivery/STATUS.json`，不能只根据页面可打开判定完成。

## 22. 异常流程

- 外部源超时/429：单源降级，其他源继续，状态保留；
- 无摘要：evidence level 为 metadata_only；
- PDF 不是 PDF、超限或解析失败：拒绝并给出可理解错误；
- LLM 不可用：确定性检索、收藏、笔记和基础结构化分析继续；
- challenge search 部分源失败：状态显示失败，置信度不提高；
- worker 中断：running 任务恢复为 pending 并记录 recovered；
- SQLite 锁：busy_timeout + WAL，不在多个主机共享同一个数据库文件。

## 23. 数据源要求

开放源优先；授权源必须服务端密钥、合法条款、未配置状态和连通性测试。不得模拟登录、不得绕过付费墙、不得把 HTML 登录页当 PDF。每条论文保留来源 ID、URL、抓取时间、raw hash 和 fixture 标记。

## 24. AI 功能边界

- LLM 不是事实源；
- 结构化输出必须通过 Pydantic/JSON Schema；
- 重要字段附 citation；
- 摘要级禁止具体参数、全文 Future Work 和实验细节；
- 系统推断的局限与作者声明分开；
- 评分不能只由 LLM 返回一个数字。

## 25. 科研主张边界

禁止：从未有人研究、确定空白、绝对创新。

允许：在本次数据源、查询和时间范围内直接证据较少；这是需要扩展检索和专家确认的候选。

## 26. 隐私和版权

- 密码使用 PBKDF2 哈希；
- 会话 token 只保存哈希；
- PDF 上传要求用户确认权利；
- 不抓取受限全文；
- 用户导出不包含密码哈希和 API Key；
- 日志不得记录密钥或完整 token。

## 27. 非功能需求

- 本地优先、断电重启可恢复；
- API P95 目标：本地 CRUD <300ms；外部搜索另行分源报告；
- SQLite WAL、外键、busy timeout；
- 25MB 默认 PDF 上限；
- 中文优先；桌面 Sider 与窄屏 Drawer 响应式，宽表横向滚动；
- 错误可理解；
- 配置集中、代码严格类型、Prompt 和工作流版本化。

## 28. 产品指标

- 首次获得有效论文时间；
- 搜索到收藏转化率；
- 详情打开率；
- 收藏后再次访问率；
- 计划创建率和完成率；
- 用户修改 AI 结果比例；
- 周留存。

## 29. AI 与检索质量指标

- Precision@10、Recall@K、NDCG@10；
- 重复论文率、源失败率和搜索延迟；
- Retrieval Hit Rate；
- Citation Precision、Citation Coverage、Faithfulness；
- Structured Extraction Accuracy；
- Missing-field refusal accuracy；
- PDF 解析失败率；
- 候选空白被 challenge 推翻比例、专家“值得查证”比例和人工修改率。

## 30. 风险

| 风险 | 影响 | 控制 |
|---|---|---|
| 数据源覆盖不足 | 错误空白 | 多源、查询扩展、引用链、低置信提示 |
| 摘要幻觉 | 错误理解 | evidence level 和字段拒答 |
| fixture 污染 | 假论文进入结论 | is_fixture 显式标记、生产默认关闭 |
| 同名作者合并 | 错误贡献 | 要求稳定作者 ID，当前不自动合并 |
| 评分伪精确 | 误导决策 | 组成分、覆盖度、版本和阻断项 |
| 用户越权 | 隐私泄漏 | 所有用户数据绑定 user_id 并测试 |
| 局域网明文 | token 暴露 | 可信内网使用；公网必须 HTTPS |
| SQLite 多主机共享 | 损坏/锁 | 单主机部署，禁止网络文件系统并发写 |
| validation 过拟合 | 研究结论不稳 | 研究计划内明确 validation-only/frozen-test |

## 31. 版本计划

- V1 RC：完成主链路和回归；
- V1 正式：联网真实源、Docker 冷启动、前端 E2E 均通过；
- V2 RC：challenge 门控和计划；
- V2 正式：专家评估集、引用链扩展和周期任务达到门槛；
- V3：仅在 V2 使用数据表明需求后进入。

## 32. 上线计划

4. Docker 冷启动；

6. 局域网 3–10 人灰度；
7. 收集失败源、错误分析、确认/拒绝和计划完成数据；

## 33. 运营与反馈计划

- 新手引导任务；
- 每次 gap 确认前强制记录反证判断；
- 收集“为什么拒绝该候选”；
- 对匹配度和复现度允许逐项反馈；
- 按研究方向、阶段和论文证据等级分组分析；
- 不用生成候选数量作为核心指标。

## 34. 已知限制

- 当前结构化分析以确定性规则为基础，不等同于成熟全文抽取模型；page/chunk provenance 不等于句子级蕴含证明；
- 引用/被引/作者卡和主题聚类仍需更完整适配器；
- Web of Science、ScienceDirect/Scopus 未接入授权凭据；
- 前端图谱可视化未达到 ResearchRabbit/Connected Papers 水平；
- 真实源质量、依赖感知前端 typecheck/Vitest/build、Playwright、MCP stdio 与 Docker 需按当前环境实际执行；无法执行必须保持 BLOCKED，不能用源码存在代替；
- 当前候选 gap 算法是透明的辅助规则，不应包装成独立基础模型创新。
