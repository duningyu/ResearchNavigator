# ResearchNavigator 2.1 Feedback Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Close the real-user feedback loop so ResearchNavigator uses explicit paper selections, evidence-grade analysis, deep comparison, explainable gap exploration, reproducible Top50 discovery search, responsive navigation, and complete operational acceptance coverage.

**Architecture:** Keep the React/FastAPI/SQLite architecture. Add small behavior-bearing tables and APIs for search ranking metadata, explicit paper sets, comparison runs, gap explanations, user settings, admin runtime config, and idempotency. Existing last-search coupling is removed by a reusable selection model; all research comparison/gap workflows snapshot explicit paper IDs plus project/profile direction context.

**Tech Stack:** Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, SQLite, HTTPX, React 19, TypeScript, Vite, Ant Design, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-27-researchnavigator-feedback-closure-design.md`

## Global Constraints

- Candidate gaps are hypotheses, never novelty proof; preserve `not_novelty_proof=true`.
- `abstract_only` must not invent experimental protocol, Future Work, author limitations, datasets, or hyperparameters absent from the abstract.
- New user-scoped endpoints require cross-user denial tests.
- Search live-source reproducibility is provenance-based, not a fixed-title promise.
- Discovery Top50 targets 10 `classic_candidate` + 40 `frontier_candidate`; shortfalls are reported rather than manufactured.
- Page size is 10; persisted result count may be 10/20/50.
- Same search-session rerun reuses its diversity seed; a new discovery search gets a new seed.
- Human confirmation generated by automation is reported only as `simulated_human_confirmation`.
- Worker acceptance requires terminal `succeeded|failed|cancelled`; `pending` is not PASS.
- Raw secrets are never returned to the browser.
- All current-checkout PASS claims require executed evidence.
